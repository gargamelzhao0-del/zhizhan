# 1.10.1 导航收展性能修复

原来同时动画化 width、height、left、bottom、padding、inset、图标尺寸，触发每帧重排；选中背景及玻璃尺寸观察器随后继续读写尺寸，形成重复工作。

chromeAnimation.ts 使用 FLIP：先读取当前可见矩形（包含尚未完成的动画），取消旧动画，提交一次目标布局，批量读取终点，再通过 Web Animations 的 transform 和 opacity 过渡。玻璃角半径补偿保持球与胶囊轮廓；这部分仍会重绘，因此不宣称所有开销都在合成线程。按钮/图标不随玻璃横向拉伸，280ms 统一节奏。所有起止读操作成组执行；选中背景的 offset 也先批量读取再写变量。没有逐帧 JavaScript、截图回放或延后业务状态。

性能脚本 scripts/profile-chrome.mjs：独立 Chrome 手机上下文，393×852、4 倍 CPU 降速，资料库 6 次滚动收起与显式展开，共 12 次。首轮实测 LayoutCount 464→72（减少84.5%），LayoutDuration 0.336s→0.067s，RecalcStyleDuration 2.064s→0.770s。此数据为固定脚本的主线程累计量，不是 FPS、用户等待时长或 S24 实机结果。报告在 docs/chrome-performance-before.json、after.json；主线程繁忙及浏览器版本会影响复测。

回归覆盖双向滚动、到顶展开、课程全程紧凑、球居中展开、搜索焦点、触控范围、安全区、旋转、输入法与编辑布局；新增快速反向位置连续性、减少动态效果取消和动画期布局尺寸固定的检查。

参考：[Chrome 动画性能指导](https://web.dev/articles/animations-and-performance/) 提倡优先动画化 transform/opacity；[Chrome 模糊动画说明](https://developer.chrome.com/blog/animated-blur?hl=en) 解释复杂模糊的绘制成本。本实现仍保留实时玻璃，不承诺任意设备的帧率。

# 1.9.1 阅读导航与玻璃过渡

普通页面使用 chromeState.ts 的位移阈值：离开顶部后任一方向累计移动 8px 收起，反向滚动不再展开；距顶部不超过 1px 或明确点击后展开。reading 标志优先，课程正文即使在顶部也保持紧凑；搜索打开只临时提供输入表面。项目和经验文章沿用普通页面行为。顶部占位和正文布局不随收展改变。

useChromeMotion 管理按路由隔离的阅读浮层状态。课程页初始为右下侧 36px 可见玻璃球，触控区域 48px；点球后移至底部中央，恢复 196×34px 可见玻璃、200×48px 触控区域的四入口导航。继续滚动、点击正文、Escape 或前端原生返回事件先收球。键盘展开后聚焦入口，键盘收回后恢复球的焦点；点击正文或搜索时不抢回焦点。隐藏入口使用 inert。路由进入、历史返回、旋转、模拟输入法、安全区和高对比度都有回归。

本轮定位到的过渡问题是尺寸变化期间仍使用上一个尺寸的 SVG 法线图，最后再替换；旧图会随表面被拉伸，复杂滤镜又增加缩放期的绘制负担。GlassMaterial.tsx 将背景拆成同级的 glass-diffusion 与 glass-refraction。ResizeObserver 发现尺寸改变时进入 moving：停用 SVG 折射，使用实时原生 backdrop blur。尺寸稳定 60ms 后生成新几何图、Image.decode 成功并再次匹配当前宽高，再进入 still，用 160ms 交叉淡入折射。异步代号、销毁标志和计时器清理防止旧任务覆盖新状态。

法线图仅缓存几何，不缓存背后页面截图；最多 16 个尺寸，最大图宽 480px，不在每个滚动帧生成。SVG 从八个处理节点简化为三个（模糊、法线图、位移）；底色透明度和模糊量降低。外层玻璃保持透明，由两个子层采样真实背景，避免父级 backdrop-filter 形成错误采样边界。高对比度/减少透明度使用实色，减少动态效果关闭过渡。保留前缀在前、标准属性在后的声明顺序。

e2e/chrome.spec.ts 增加逐帧检查：变形时旧尺寸 SVG 不生效、无横向溢出，停稳后恢复折射；检查球展开后的导航水平居中。audit-glass-optics.mjs 单独关闭位移或柔化，确认真实渲染像素改变。截图和录像位于 release/previews/1.9.1。浏览器检查不能证明 Samsung S24 实际 GPU 帧率；WebView 不同版本仍需实机确认。这是浏览器材质近似，不是 Apple 原生 Liquid Glass 引擎。

# 1.9.0 自适应玻璃导航

参考 Apple [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass) 的导航与滚动收起原则，在 Android/WebView 中实现对应的控件层。新增 chrome.css 只负责上下导航的玻璃风格与两种几何状态；这不是苹果原生折射引擎。

顶部 header 保持原文档占位，topbar-surface 缩为 48×48 CSS px 的点击区域，内层玻璃可见直径为 44px。底部固定导航收为 200×48 CSS px 的触控区域，玻璃内缩后可见面积为 196×34px，距离底部安全区 8px。四个入口各保留至少 48×48px，图标缩为 18px，名称通过 aria-label 保留。可见的玻璃与点击区域分离，因此能更扁平而不缩小触控目标。正文高度和底部安全留白不随状态变化，内容可以从浮动控件之间穿过。

chromeState.ts 纯函数管理滚动方向和防抖：离开顶部至少 96px 且同向向下移动达到 28px 收起，反向回滑达到 22px 展开，顶部 24px 内始终展开；滚动位置夹在文档范围内，忽略弹性越界。useChromeMotion 用被动 scroll + requestAnimationFrame 更新少量 dataset，不按帧触发 React 重渲染。路由变化、搜索、弹窗、键盘焦点和方向切换重新评估状态；点击紧凑导航直接完成导航，当前标签重复点击也会展开。

搜索展开后锁定完整导航，保留输入焦点。聚焦文本输入且 visualViewport 相对基准高度减少超过 120px 时隐藏底部浮层；宽度变化重建基准，排除缩放比例变化。此为浏览器推断，不是原生 IME 回调，浮动键盘或厂商输入法需实机核对。编辑页保留原本静态底部导航安排。

SelectionGroup 的 ResizeObserver 跟随胶囊尺寸同步选中背景，在尺寸变化期间关闭该背景的二次追赶过渡，稳定后恢复平滑选中动画。没有选中项时隐藏选中背景。展开/收起在 360ms 内完成，并同步调整底部位置；减少动态效果时直接切换。

依据 Apple [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 重新制作材质，而不是在厚白底上增加模糊。GlassMaterial.tsx 为两个小范围导航背景创建胶囊法线图：中心保持平稳，边缘用 feDisplacementMap 对背后画面做局部位移，叠加轻微模糊、低透明度底色和双向细高光。SVG 仅影响装饰背景，不扭曲前景图标和文字。法线图最大宽度 480px，尺寸稳定 100ms 后才重新生成，不在滚动帧中重画画布，也没有常驻动画循环。CSS 背景滤镜的语法依据 [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)。这仍是浏览器近似效果，不是 Apple 原生光学引擎；实际 Android GPU 成本和不同内核对 SVG 背景滤镜的支持仍需真机验证。

没有法线图时使用模糊回退；减少透明度、高对比度及不支持背景模糊时使用实色。改变高对比度偏好会释放或重建法线图。文字密集的阅读区域仍使用不透明内容底，只对上下两块装饰表面处理背景。

折射边缘与中央文字柔化使用独立遮罩组合。隐藏 SVG 的视口为零，feImage 不使用百分比尺寸，改为实际材质的 CSS 像素宽高，防止样式显示滤镜已开启但法线图实际未正确参与绘制。audit-glass-optics.mjs 在独立页面的稳定条纹背景上比较截图：分别关闭折射位移和中央柔化，要求实际渲染像素改变；该检查已纳入发布门槛。截图检查不能代替真机帧率测量。

新增 tests/chromeState.test.ts 验证阈值、防抖、锁定、顶部和底部越界；e2e/chrome.spec.ts 验证滚动位置稳定、点击尺寸、反向展开、搜索焦点、直接导航、模拟键盘缩屏、横屏和减少动态效果。audit-adaptive-chrome.mjs 覆盖 5 种手机/横屏尺寸 × 2 个主题 × 3 个页面，共 30 组滚动态检查，已加入发布门槛。预览位于 release/previews/1.9。

本轮正式构建暴露了 CSS 前缀顺序问题：回退规则中若把 -webkit-backdrop-filter 放在标准属性后面，当前压缩器会只保留前缀声明，而本机 Chromium 不识别这一前缀，导致标准 blur 继续生效。已统一为前缀在前、标准属性在后，且在实际打包后的页面上验证高对比度，不仅检查开发服务器。

# 1.8.0 视觉与交互维护

本轮依据 Apple [材质规范](https://developer.apple.com/design/human-interface-guidelines/materials)、[动效规范](https://developer.apple.com/design/human-interface-guidelines/motion) 和 [WWDC25 Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 区分内容层与操作层。正文采用不透明底色，浮动导航采用轻度模糊、边缘高光与阴影。首页主卡片、课程封面和页面文案重新处理。本项目仍是 Android/WebView 应用；这些是 CSS/WAAPI 实现，不是苹果原生 Liquid Glass 的折射引擎，也没有复制 Apple 字体或图标资产。

design.css 管理视觉 tokens、排版和布局，interactions.css 管理操作反馈、选中背景、导航材质与降级，motion.tsx 管理短时过渡的生命周期。SelectionGroup 通过实际按钮几何信息定位同一个 selection-lens，ResizeObserver 在字体和窗口变化后重测；观察器不随阅读进度更新反复创建。选中状态通过 aria-current/aria-pressed 即时更新，动效不延迟路由或数据写入。

动效节奏：按压进入约 70–80ms，释放约 220ms，页面进入 230ms，少量卡片分批进入最长约 356ms，选中背景 340ms，弹窗进入 320ms、退出 160ms。只有进入、触控、状态变化时播放，不设置循环装饰动效。主要位移用 transform/translate/scale 与 opacity；选中背景随尺寸变化有有限 width/height 过渡，课程折叠需要布局变化，不能宣称所有动画都只在合成线程执行。

useEnterMotion 在新导航和卸载时取消旧动画；系统中途切到减少动态效果时取消进入过渡。弹窗保留焦点约束、滚动锁与关闭后的焦点恢复，中途减少动态效果会直接结束关闭动画。SelectionGroup 的移动由 CSS 过渡接续，快速切换不排队等待。课程 details 使用 interpolate-size 和 ::details-content 渐进增强；不支持时保留原生即时展开。Reveal 中折叠内容继续 inert，草稿保留。

减少动态效果关闭 CSS 动画、过渡与按压缩放；减少透明度或高对比度改用实色导航。prefers-* 是浏览器提供的偏好，Android 设置是否映射到特定 WebView 需真机检查。动画已验证可打断及结束后无常驻运行实例，不据此推断 S24 稳定 60/120fps。

e2e/polish.spec.ts 验证快速导航、分类和横屏后的选中背景对齐，运行中减少动态效果、弹窗关闭后的滚动恢复、收藏持久化和高对比度实色回退。既有编辑、草稿、导入、更新与数据迁移回归仍须全部通过。页面检查继续覆盖 112 个布局组合和 76 篇资料；最终数量以当前验收记录与发布清单为准。

## 数据模型

数据库名 `zhizhan-v1`，采用 IndexedDB/Dexie，模式版本为 1。`shelves` 保存知识库，`articles` 保存正文、标签、笔记、收藏、阅读进度、复习时间、版本号与删除时间。`attachments` 用 Blob 保存原文件，`revisions` 保存最近 30 次编辑前的文章快照，`settings` 保存初始化标志和阅读设置。

正常升级不能改变 origin 或数据库名。新增字段或索引时增加 Dexie 模式版本并编写迁移，不能删库重建。初始化在一个事务中写入 seed；只有完成后才设置 initialized。内置资料更新使用 contentVersion 和 builtinContent 摘要记录。未修改正文更新时保留笔记与学习状态，保存旧版本；已修改正文保留原文并生成新版副本，重写新版引用。回收站不复活，重复更新幂等。1.0.0/1.0.1 的原文摘要来自已交付 APK，保存在 content/legacy-seed-hashes.json。

编辑器保留内存草稿与本地紧急草稿，500 ms 防抖提交。写入事务比较文章 version，成功后递增。保存正文时只更新标题、正文、标签和所属知识库，避免把旧快照中的笔记、收藏和进度写回。笔记独立比较上次已保存文本，串行保存输入期间产生的新内容。紧急草稿保存 value 与 base，重新打开后仍使用原始基线比较；旧版无基线草稿只恢复展示，不自动覆盖新笔记，可另存文章。标签输入保留用户正在输入的原字符串，解析后去重，避免即时删除逗号。

回收站使用 deletedAt，不移除文章与附件。首版不提供破坏性的附件垃圾回收；未来回收必须扫描正文、笔记、所有历史版本和回收站引用。

## 引用格式与资料包

正文使用 `doc:文章ID` 和 `asset:附件ID` 链接，渲染器拦截并在应用内处理。外部链接仅接受 http、https、mailto 等明确类型，原始 HTML 不执行；远程图片不会自动加载。流程图用 Mermaid strict 模式、纯 SVG 标签和 DOMPurify 处理，过长或无法解析时回退为源码。

完整备份的 `manifest.json` 定义 `format=zhizhan`、`version=1`、知识库、文章、历史、设置和附件清单。附件保存在 `assets/ID/原文件名`，包含 size 与 SHA-256。额外的 `markdown/ID.md` 使用相对路径指向其他文章或附件，可以在应用外使用。

导入检查 ZIP 结束目录、路径、文件数量、大小、CRC、模式版本与字段，再验证每个附件 SHA-256。写入在一个 Dexie 事务内完成；导入冲突保留副本，以 Markdown AST 重写新增文章中的内部引用，不改代码示例。发生文章冲突时，按反向引用图传播副本需求，保证目录、相互引用和循环链接指向同一套导入副本。导入不是还原覆盖模式，也不是两个数据库之间的三方合并。

容量边界见使用说明。首次引入更大的附件或资料包时，应评估全文检索工作线程，并增加大包内存预算与真机压力测试。1.0.1 已将 ZIP 压缩、受限解压和 CRC 移到独立 Worker，使用 transferable 缓冲区，完成或失败即终止线程。Markdown AST、清单 JSON 及部分 Blob 操作仍在主线程；还需真机内存压力测试。

## Android 导出

Web 层将待导出 Blob 切成 192 KiB 分片传给原生插件，插件顺序写私有临时文件。准备完成后调用 ACTION_CREATE_DOCUMENT，让用户选择保存位置，再以 64 KiB 缓冲复制到目标 URI。成功后清理暂存文件，取消时返回取消结果；失败不记录成功备份。

这种方式不要求共享存储的广泛权限。Android Manifest 禁止系统自动备份，1.2.0 为更新功能新增 INTERNET 与 REQUEST_INSTALL_PACKAGES，禁止明文流量。Web CSP 的 connect-src 允许 HTTPS 用于可配置发布地址，脚本仍仅加载本地资源，远程图片不自动加载。应用卸载或清除数据会移除 IndexedDB。SAF、选择器取消和厂商文件管理器行为仍需要目标手机验收。

## 应用更新

发布地址、自动检查、最近尝试与忽略版本保存在 settings 的 appUpdate* 键中。自动检查通过数据库事务占用每天一次的检查机会，多个窗口不重复自动检查；手动检查绕过时间限制。URL 变化丢弃旧候选；操作 ID 关联进度和取消，防止旧下载回调重新开放安装入口。

Android 使用独立工作线程处理网络与文件，不把 APK 转成 Base64 经桥传输。流式限制清单 64 KiB、安装包 128 MiB，核对长度、SHA-256、包名、真实版本、最低 SDK 和完整签名集合。安装前重复校验缓存，再通过 FileProvider 给系统安装器临时只读权限。签名轮换、持久后台任务和断点续传未实现。

`scripts/package-update.mjs` 从真实 APK 和 release-notes.json 生成相对路径清单；最终发布脚本检查 APK/dist/资料一致，生成可上传 ZIP。使用详情见 [更新功能与发布指南](更新功能与发布指南.md)。
