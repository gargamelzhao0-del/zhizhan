# 知栈 1.5.0 本轮修复与课程复核

日期：2026-10-08。本轮针对三星 S24 的“更新内置资料”报错处理 Android 特定路由问题，并深化课程内容。安装包是手机验收候选版；构建、浏览器模拟和资源逐字节验证不替代 S24 真机测试。

## 已确认的问题

Capacitor 8.5.2 的 WebViewLocalServer 在 HTML5 路由模式下把末段不含点号的路径作为页面处理。旧 APK 的 142 个内置附件恰好全为无扩展名地址，因此返回 index.html 而不是附件，SHA-256 正确地拒绝了错误字节。桌面服务器不会触发这个原生规则，这是上一版桌面检查漏掉的边界。

修复使用带内容摘要的 .bin 地址，原附件身份保留。请求不复用缓存，二进制读取后按可信内置清单设置 MIME；校验仍在数据库写入前完成。发布门槛增加 APK 内清单、附件路径、附件摘要与 dist 一致性。真实 1.4.0 APK 的目录清单作为回归输入，另外模拟原生路由复现失败；测试明确标为浏览器模拟。

## 教材改进与质量判断

保留每门 20 篇的学习路线，深化 C++ 全部 20 篇和 Linux 16 篇。排除 fenced code 后，两门课程由 61,129 字符增至 108,786 字符；字数仅说明工作范围，不证明教学质量。全库 76 篇、149 附件。

C++ 加强变量与表达式逐步求值、借用与所有权、容量和复杂度、失败提交、条件变量状态机、发布同步链、字节协议和独立测试判据。提供五文件 sample_audit 工程，明确上限、超长行恢复、输出失败、退出码和可重复构建。该工程已在 Windows 构建并通过 11 项核心断言、6 项 CLI 场景、2 项 CTest；原有 17 个 C++ 示例的 52 项检查、3 项 CTest 和 8 项 TCP 检查继续以源码摘要核对有效。

Linux 加强环境、启动、进程/文件描述符、短写、虚拟内存、线程关闭、TCP 边界、设备树地址、驱动资源、交叉编译、poll 超时与停止、可靠提交、交付取证。完整 poll 示例和用户级服务配置均随文附带；区分可运行的单次审计部署基线与尚需实现验收的常驻采集服务，不把作业需求冒充已完成程序。

## 正式交付仍需通过的门槛

**P0：S24 安装与实际运行。** 先取得手机完整安装提示及 Android/One UI 版本，必要时在用户连接并授权调试后获取准确安装错误码。当前静态检查没有证实根因，不能把 Samsung 自动拦截器当成已确认原因，更不能让用户先卸载来试错。

**P0：原生数据闭环。** 在 S24 验证首次初始化、飞行模式重开、中文软键盘、系统返回、附件选择、备份成功/取消、回导、进程结束后重开和同签名覆盖升级。至少保留一份导出文件并验证哈希/回导内容。

**P1：学习内容试学。** 初学者按 Linux 与 C++ 路线各完成一条实验链，记录在哪一步必须求助；Linux 真实运行结果补入实验记录后才能标为平台验收通过。复杂主题后续可增加图解、综合作业与更多平台适配，不能用虚构运行结果提前通过。

**P1：容量与长时间使用。** 接近 128 MiB 资料包边界、低可用空间、长期积累与目标手机 WebView 内存压力仍待实测。Worker 减少压缩阻塞，但部分清单和 Markdown 处理仍在主线程。先以中小型文本、代码和附件使用，并维持独立备份。

自动审批曾拒绝创建/启动 Android 模拟器，返回信息仅为“策略阻止”；没有绕过限制。当前也没有连接 Android 真机。故本报告不会把 Android 运行列为已通过。
