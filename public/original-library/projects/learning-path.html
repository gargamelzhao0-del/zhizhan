从零基础到独立嵌入式项目

目标是交付一个能运行、能排错、能恢复的嵌入式项目。27 册是按需调用的知识库，无需按编号通读。先完成一条硬件路线，再扩展语言或平台。

把时间花在可验证的能力上

单次学习可先按 25 分钟阅读、45 分钟实现、10 分钟复盘安排（规划起点，不是完成承诺）。读前尝试任务，能独立完成就跳过；做不出时只回查阻塞点。安装、接线和排错时间单独记录。

每站保留“需求→实现→正常/失败证据→修复→变更后的再验证”。隔 2–3 天不看答案再做一次，检验迁移和保留效果。阅读收益看能否独立完成这些动作，不统计累计字数或阅读时长排名。

第 1 站

起步：能构建和诊断

开发工作站与环境边界 → Linux 命令行与文件系统 → Git 与变更管理 → 构建与依赖管理 → 程序是怎么跑起来的 → 多文件、头文件与 Makefile

离站条件：从新目录构建两文件程序；制造编译错和链接错，分别找出原因。不要为了开始项目先通读所有语言。

第 2 站

C 基础：把数据处理写正确

变量、类型与表达式 → 控制流 → 函数与作用域 → 数组与字符串 → 指针入门 → 结构体、枚举与 typedef → 综合小项目与过渡到精读 → 标准库、输入解析与错误处理

离站条件：独立写采样记录 CLI，正确处理空值、边界、坏输入。卡在指针就回看对象图；不急于学动态分配和复杂回调。

第 3 站

第一块板：能解释每根线与每个时钟

电路基本量与测量 → 数字电平与引脚电气 → 电源、去耦与复位 → 时钟与最小系统 → 接口电路与总线物理层 → 示波器与逻辑分析仪 → 时钟树与启动 → GPIO 深入 → 中断与 NVIC

离站条件：只选一种板，交付接线、供电检查、下载/调试方法和 GPIO/中断现象。没有板时可先看模型，但此站验收保持待完成。

第 4 站

采样链：从外设到可验证的数据

定时器 → ADC / DAC → DMA → UART → 传感器驱动实战 → 指针：从地址到硬件 → 位操作与寄存器级编程 → 调试、诊断与工具链 → 协议设计基础 → 校验与完整性

离站条件：完成定时采样、固定容量缓冲和协议帧；用 P01 对照分片/坏帧/重同步。查 B01 当前问题的小节，不要求整章一口气读完。

第 5 站

工具与回放：让问题能复现

函数 → 字符串与文件 → 异常、迭代器与测试 → 环境、包与项目组织 → 测试、CLI 与综合项目 → 串口与协议工具链 → 数据契约、回放与实验复现

离站条件：需要时补 B04a 的基本类型和控制流。保存原始流、单位、时基和版本；再次回放得到相同解析结果。

第 6 站

并发与故障：让慢任务不拖垮系统

为什么需要 RTOS → 任务与调度 → 同步原语 → 队列、事件组与流缓冲 → 中断与 RTOS 的边界 → 时间管理 → RT-Thread 与 Zephyr 对照 → 实时预算与可调度性

离站条件：把现有采样链迁入一种真实 SDK；写响应预算、队列满政策，注入慢消费者。需求简单时可用裸机状态机，并写明取舍依据。

第 7 站

交付一个完整项目

从需求到架构 → 工程骨架 → 数据采集与本地存储 → 可靠性与自恢复 → 综合项目 A · 智能环境监测终端 → 参数与数据的持久化设计 → 产品级应用验收 → 静态分析与自动化门禁 → 单元测试与仿真 → 需求、接口与风险驱动测试 → 发布、生产与现场闭环

离站条件：从空工程完成环境监测终端；另一人依说明构建、烧录、诊断和恢复。发布不能只交一个没有来源的二进制。

第 8 站

联网时再加入信任与升级

应用层协议 → OTA 全链路 → 断网、背压与端到端可靠性 → 升级确认与版本兼容深化 → 资产、威胁与信任边界 → 设备身份与密钥生命周期 → 安全启动与固件真实性 → 通信安全与证书验证 → 升级安全与回退策略

离站条件：只有联网/远程升级需求才进入本站。签名、版本、设备适配和健康确认分别验证；断网、重试和断电均有明确结果。

完成基础项目以后选择分支

  • C++：B02a→B02；Rust：B03a→B03。选择一种满足团队、生态与资源约束的语言。
  • Linux 网关：B16 的命令行/构建→B09→B11；确需新器件驱动再读 B10。
  • 控制与信号：B19 的数值/统计→B20 对应机制→B23 温控回放；实机另验。
  • 端侧 AI：B21 数据切分与基线→B13 模型及运行时→B14 业务闭环。先证明比简单规则有收益。
  • 前沿专项：B15 是选型入口。ROS 2、FPGA、大模型、Matter 需要各自的工程与硬件，不能靠一章概览声称掌握。
