Module 01 · 实时基础

为什么需要 RTOS.

前后台轮询的定量缺陷；响应抖动来自哪里；RTOS 的成本（RAM/Flash/复杂度）；什么时候不该用。

前置：了解裸机前后台（super-loop）轮询结构，以及“周期/执行时间”的含义。◷ 约 44 分钟◈ STM32F103 / ESP32 / STM32H7 三平台对照⚑ 主机模型；目标构建与测量按章验收能力目标：能定量指出前后台轮询的响应抖动来源，用利用率筛查过载，再用含阻塞/抖动的响应时间分析判断截止期。
本章速览
  • 前后台轮询的响应时间 = 所有任务执行时间之和，慢任务会直接拖慢快任务。
  • RTOS 用“可抢占 + 优先级”把响应时间解耦；代价是每个任务一块栈与切换开销。
  • 先问“抖动/截止期真的需要吗”：不需要就别上 RTOS，简单可靠优先。

1.1 前后台轮询的结构性缺陷

一句话：前后台（super-loop）里，快任务的响应时间等于循环里所有任务执行时间之和。只要有一个慢任务在忙，快任务就得等——这是“抖动”的结构性来源，与代码写得对不对无关。

1.5 常见误区与排障

失败路径与排障
  • “有任务就是 RTOS”：把顺序函数塞进多个任务但不设优先级，只是把问题搬进并发。
  • 忽略栈成本：每任务大栈让 RAM 见底，应按最坏调用链给并用高水位校正。
  • 认为 RTOS 保证实时：实时性来自可调度性分析 + 优先级分配，不是内核本身。
  • 没有期限也上 RTOS：白增 RAM/功耗/复杂度。
◆ 自测 · Module 01（先答再看）

  1. 前后台里慢任务 5ms、快任务要 1ms 响应；“把慢任务优化到 4ms”为什么不解决快任务抖动？

    查看答案

    快任务响应仍等于循环总耗时，只要慢任务存在就要等它跑完。要解耦必须让快任务能被独立抢占（RTOS），或把慢任务切成可中断的小段。

  2. “上了 RTOS 就实时”对吗？

    查看答案

    不对。实时性来自“可调度性分析 + 优先级分配 + WCET 预算”。内核只是保证可抢占，若任务集有期限冲突仍会超期。

  3. 什么时候不该用 RTOS？

    查看答案

    没有“必须在固定期限内响应的并发活动”时。前后台 + 状态机往往更省 RAM、更省电、更好验证。

2.5 常见误区与排障

失败路径与排障
  • PendSV 设成高优先级：切换会打断中断，中断延迟不可控。
  • 任务栈不对齐：Cortex-M 异常入栈要求 8 字节对齐。
  • 把大工作放进高优先级任务：低优先级（含空闲）饿死，看门狗超时。
  • 用 delay 做周期：会漂移，应用 vTaskDelayUntil。
◆ 自测 · Module 02（先答再看）

  1. 为什么上下文切换放在最低优先级的 PendSV？

    查看答案

    任何中断都能先执行完，切换只在所有中断处理完后发生；中断响应不会被“正在切换”挡住，也避免在中断里直接切栈的竞态。

  2. 两个同优先级任务都不主动阻塞会怎样？

    查看答案

    时间片轮转让它们在彼此间交替，但更低优先级任务永远得不到运行（被饿死）。要给低优先级留出让点或提优先级。

  3. 上下文切换的实质保存/恢复什么？

    查看答案

    硬件进场已压 r0-r3/r12/lr/pc/xPSR；端口层再保存 r4-r11，把 SP 存进 TCB，从下一个 TCB 恢复 SP 与 r4-r11，并切 PSP。

  1. 二值信号量能用来保护共享缓冲区吗？

    查看答案

    不该。它没有所有权、不做优先级继承，用作锁会导致优先级反转；应用互斥量。只有“一个任务 give、另一个 take”的通知语义才适合二值信号量。

  2. 优先级继承如何限制反转？

    查看答案

    阻塞时让持有锁的低优先级任务临时升到等待者的高优先级，使中优先级任务无法抢占它，把反转限制在一个临界区以内。

  3. 中断里为什么要用 FromISR 版？

    查看答案

    普通 API 可能阻塞，中断不能阻塞。FromISR 版不阻塞，用 xHigherPriorityTaskWoken 表示是否唤醒了更高优先级任务，再由 portYIELD_FROM_ISR 决定是否切换。

5.1 中断只做“取数据+清标志+唤醒”

中断优先级高于任何任务，所以 ISR 里唯一该做的是取数据 + 清标志 + 唤醒任务。在 ISR 里做长工作会拉高所有任务和其它中断的延迟。

5.5 常见误区与排障

  • ISR 里用普通 xQueueSend/xSemaphoreTake：可能阻塞，行为异常。

7.5 常见误区与排障

失败路径与排障
  • 用 vTaskDelay 做周期：周期被拉长（执行+延时），长期漂移。
  • 软件定时器回调做长活：阻塞定时器服务任务，拖慢所有软件定时器。
  • tickless 无可靠低功耗时基：唤醒点不准，系统时间漂移。
  • tick 频率过高：空闲频繁唤醒，功耗与切换开销上升。

10.5 常见误区与排障

失败路径与排障
  • 按函数而非截止期拆任务：优先级失去意义。
  • 队列深度拍脑袋：太浅丢数据，太深吃 RAM。
  • 阻塞调用不设超时：一个设备无响应卡死整个任务链。
  • 持锁期间做 I/O：把总线锁住很久，其它任务集体阻塞。
◆ 自测 · Module 10（先答再看）

  1. 采样 10ms、上报 100ms、控制 1ms，优先级从高到低怎么排？

    查看答案

    控制(1ms) > 采样(10ms) > 上报(100ms)。周期越短、越接近截止期的任务优先级越高（RM 的思路）。

  2. 队列深度应该怎么给？

    查看答案

    按“最坏突发量 / 消费速率”估算，宁深勿浅但要算 RAM；太深会掩盖上游过快的问题。

  3. 为什么每个阻塞调用都要有超时？

    查看答案

    一个设备无响应会让该任务无限等待，进而卡死依赖它的整条任务链。有超时才能降级/恢复。

11.5 常见误区与排障

  • 用平均时间当 WCET：最坏分支才决定截止期。

12.5 常见误区与排障

失败路径与排障
  • 用关本核中断保护跨核数据：另一核照样并发。
  • 自旋锁持有期间调阻塞 API：可能死锁。
  • 忘记 cache 维护：DMA 写入后 CPU 读到旧值。
  • 删除任务不释放资源：锁/内存泄漏，最终卡死。
◆ 自测 · Module 12（先答再看）

  1. 为什么单核“关中断”在多核上不够？

    查看答案

    关本核中断只阻止本核被抢占，挡不住另一个核同时读写同一内存。多核必须用自旋锁/原子保证跨核互斥。

  2. Cache 一致性怎么维护？

    查看答案

    共享缓冲放非 cache 区，或按 cache line 对齐并做 clean（CPU→内存）/invalidate（内存→CPU），DMA 前后按方向维护。

  3. 删除任务前必须做什么？

    查看答案

    释放它持有的锁、内存与句柄。挂起只是暂停、不释放资源；反复删除/重建会引入碎片。

术语 · Glossary

术语表.

按“先定义、再结论”的方式收口；FreeRTOS/ESP-IDF/Zephyr 的叫法差异一并标注。

按“先定义、再结论”的方式收口；不同内核对同一概念的叫法差异也标注在此。

任务 / 线程 (Task)
独立执行流：有自己的栈、TCB 与优先级；是调度的基本单位。
TCB
任务控制块，保存任务状态、栈顶指针、优先级、延时与阻塞信息。
上下文切换 (Context Switch)
保存当前任务寄存器、恢复下一个任务寄存器；Cortex-M 上在 PendSV 完成。
PendSV
Cortex-M 最低优先级的可挂起异常，专用于上下文切换，保证中断优先处理完。
抢占 (Preemption)
更高优先级任务就绪时立即夺取 CPU；固定优先级系统靠它保证截止期。
时间片轮转 (Round-Robin)
同优先级任务按 tick 轮流运行，避免同级饿死。
优先级反转 (Priority Inversion)
高优先级任务被持有锁的低优先级任务挡住，又被中优先级任务无限拖延。
优先级继承 / 天花板
持锁的低优先级任务临时继承等待者的优先级（或提升到天花板），限制反转。
临界区 (Critical Section)
访问共享资源时不可被打断的区间；长度直接决定中断延迟。
FromISR
中断安全版的同步 API；它用“唤醒标志”表达是否需要切换，而非直接阻塞。
信号量 / 计数 / 二值
用于同步与计数；二值信号量没有所有权、不做优先级继承。
互斥量 (Mutex)
带所有权的锁，用于保护临界资源；阻塞时参与优先级继承。
队列 (Queue)
定长消息、按值拷贝的线程安全 FIFO；中断可用 FromISR 入队。
事件组 (Event Group)
用一组位标志表达“多个条件”，可等待“全部”或“任一”置位。
流缓冲 / 消息缓冲
流缓冲是字节流无边界；消息缓冲保留长度前缀，适合不定长消息。
tick / tickless
tick 是内核心跳；tickless 在空闲时关掉周期节拍，睡到下一个到期事件。
WCET
最坏情况执行时间；用测量并覆盖最坏分支得到，不是平均时间。
可调度性 / 响应时间分析
R_i = C_i + Σceil(R_i/T_j)·C_j，R_i ≤ T_i 才满足截止期；RM 界是充分条件。
SMP / 亲和 (Affinity)
多核下任务可固定到某核；跨核共享数据必须自旋锁/原子。
自旋锁 (Spinlock)
多核互斥：忙等直到拿到锁；单核上等价于短临界区。
栈高水位 (High Water Mark)
任务运行中栈剩余的最小值；据此校正栈大小、发现溢出趋势。
看门狗 (Watchdog)
超时未喂就复位；应由被监控的关键任务自己喂，且喂狗条件与业务完成挂钩。
阻塞 (Blocked) / 就绪 (Ready)
因等待事件/延时而不能运行 vs 具备运行条件、等待被调度。
