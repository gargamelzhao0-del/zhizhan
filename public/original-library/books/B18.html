Module 01 · ISA 与地址空间

MCU、MPU 与 SoC.

同样一行读取代码，落在 SRAM、落在外设寄存器、落在未映射区，行为完全不同。本章不背名字，而是用三个硬指标（有没有 MMU、外设集成度、总线与地址映射）把 MCU / MPU / SoC 分开，并把“地址”还原成硬件上真实存在的区域与属性。

前置：会写 C、用过寄存器；知道“指针就是地址”。◷ 约 42 分钟◈ Cortex-M / Cortex-A / RISC-V 对照⚑ 主机模型；目标构建与测量按章验收能力目标：能区分 MCU/MPU/SoC，读懂一颗芯片的地址映射与总线层次，并把关键数据放在正确的存储上。
本章速览
  • MCU/MPU/SoC 分界在 MMU、外设集成与总线。
  • 地址映射与总线层次决定访问特性。

1.1 三者的真实分界：不看名字，看三个硬指标

市面上把 MCU/MPU/SoC 讲成“小/中/大”，但这解释不了工程问题。真正决定代码行为的是三件事：有没有 MMU（决定能否跑虚拟内存/通用 OS）、外设集成度（决定是否“一颗芯片全包”）、总线与地址映射（决定性能与访问合法性）。

表 1.1 MCU / MPU / SoC 的硬指标对比
硬指标MCUMPU（微处理器单元）SoC
MMU / 虚拟内存无（可选 MPU 保护）有通常有（多核）

同一颗芯片可能跨类：带 MMU 的高端 MCU 也能跑 Linux；集成度高的 SoC 也带 RTOS 核。
这一章里“MPU”有两个意思

本章的 MPU 指 Microprocessor Unit（微处理器单元）；在 M05 里 MPU 指 Memory Protection Unit（内存保护单元）。两者缩写相同、含义完全不同，读到时先看上下文。

1.2 统一编址：外设不过是“某个地址”

在 ARM Cortex-M / RISC-V 的片上系统里，内存与外设共享同一地址空间（memory-mapped I/O）。写外设寄存器就是写内存，区别只在于该区域被总线标成 device / strong 属性：不可缓存、不可重排、按序访问。

0x40021018 与 0xE000E010 被标为 IO/device —— 访问它们走的是外设总线，不是访问 SRAM 的路径。

位带（Bit-band）别名的公式

SRAM 位带区 0x2000_0000 的任意位，都在别名区 0x2200_0000 有一个“一个字控制一位”的映射：
alias = 0x22000000 + (addr-0x20000000)*32 + bit*4。外设区同理，基址 0x4200_0000。这让“原子置位/清位”可以用一次普通写完成。

1.3 总线与互联：AHB / APB / AXI 决定“快不快”

核心并不是直接连外设，而是通过总线矩阵/bus fabric访问不同的从设备。高速的走 AHB/AXI（可接 Flash、SRAM、DMA），低速外设挂在 APB 上（UART/定时器），一次跨总线访问的代价远高于一次片上 SRAM 访问。

表 1.3 总线分层与访问代价
总线定位典型从设备相对代价
AHB / AXI高带宽、可流水Flash/SRAM/DMA/GPU低
APB低功耗、简单UART/I2C/SPI/定时器高（多周期）
TCM (ITCM/DTCM)紧耦合、零等待关键代码/栈最低（旁路缓存）

TCM 的意义

紧耦合存储 (TCM) 直连内核，无 cache 命中不确定性。把中断服务程序、实时控制回路放进 TCM/ITCM，抖动和延迟都更可控。这与 M04 的局部性优化是同一目标。

packed 是把双刃剑

__attribute__((packed)) 能对齐硬件偏移，但会让字段非对齐：在 Cortex-M0 等不支持非对齐访问的核上，读一个 packed 的 uint32 会触发 HardFault。正确做法是：用 uint32_t 字段 + 显式保留位让布局天然对齐，而不是靠 packed 硬压。

1.6 外设寄存器的正确访问：读改写 (RMW) 的陷阱

外设寄存器常是“多位共享一个字”：一个位是使能，几位是模式，几位是状态。如果两个中断源（或线程）都对同一寄存器做 读→改→写，就会互相覆盖——丢失更新。下面这段主机程序把整个竞态“跑出来”给你看：

1.8 常见误区与排障

失败路径与排障
  • 把“MPU”当同一个东西：微处理器单元 ≠ 内存保护单元（见 1.1 提示框）。
  • 误访问未映射地址：不是返回 0，而是总线故障（fault）；调试时先查地址是否在映射内。
  • 把热点代码/数据放在慢存储：跨总线访问让实时性变差，优先放 TCM/SRAM。
  • 忽略结构体填充：寄存器偏移错位 → 写到相邻寄存器，现象诡异难查。
  • 认为“主频高就一定快”：访存与总线层次常才是瓶颈（见 M09）。

  1. MCU 与 MPU（微处理器单元）最关键的一个区别是什么？

3.1 异常模型：硬件发起的“异步调用”

3.2 优先级与抢占：谁先响应

中断常同时到达，靠优先级裁决。Cortex-M 的 NVIC 采用可抢占优先级：数值越小优先级越高，高抢占优先级可以打断正在执行的低优先级 ISR（嵌套）。下面这段主机程序用一个离散事件模型，把抢占时间线真实地跑出来：

3.4 特权级与双栈：隔离从哪来

“谁能做什么”由特权级决定。Cortex-M 有 Thread/Handler 两种模式与特权/非特权两种级别；Cortex-A 有 EL0–EL3 异常级；RISC-V 有 M/S/U 三级。特权级是操作系统隔离与安全的基础。

为什么 RTOS 用双栈 (MSP/PSP)

内核（含所有 ISR）用 MSP，任务用 PSP。这样中断永远有一个“干净的栈”，不会因为某个任务栈溢出而拖垮整个内核；任务切换时只需换 PSP。这是“任务栈 + 独立中断栈”的实现基础。

失败路径与排障
  • 优先级配错：抢占优先级相同 → 高优先级不嵌套，实时性不达预期。
  • 栈按单 ISR 用量留：忽略嵌套 → 溢出改坏数据。

4.1 为什么要分层：速度、容量、成本的三角

寄存器的速度接近 CPU，但数量极少；主存容量大但慢一两个数量级。cache 夹在中间：用“最近用过的东西更可能再用”（局部性）的假设，把“慢而大”伪装成“快而够用”。这层假设成立与否，直接决定性能。

4.2 局部性：cache 能生效的唯一理由

cache 之所以有用，靠两种局部性：时间局部性（刚用过的很可能再用）与空间局部性（用了某地址，附近地址很可能马上用）。cache 以 cache line（行）为单位载入——读一个字节往往连带载入一整行。

一句话抓住 cache 的本质

cache 命中的是“行”而不是“字节”。所以：顺序访问把整行都用上（空间局部性好）；跳着访问只用行里一个字，其余白载（浪费）；反复访问同一小块数据能命中（时间局部性好）。下一节的真实命中率就是这三种的量化对照。

4.4 写策略与“一致性预告”

写比读复杂：命中时是“写透 (write-through)”还是“写回 (write-back)”？未命中时是“写分配”还是“不分配”？这些决定了内存与 cache 何时一致——而这正是 M06 DMA 与 M07 多核要处理的问题。

4.6 常见误区与排障

失败路径与排障

5.1 为什么要有“翻译”和“保护”

如果所有代码直接访问物理地址：一个野指针能改内核、一个越界能毁外设、多个程序无法各自“以为”自己独占内存。MMU 用两层能力解决：翻译（虚拟地址 → 物理地址，让每个进程拥有独立地址空间）与 权限（只读/可写/可执行，越权即故障）。

翻译 + 权限 = 隔离

翻译让“地址空间”成为可编排的资源；权限让越界必然失败。没有权限的翻译只是“换个编号”，没有隔离意义。安全（B22）与虚拟化都建立在这两点上。

Module 06 · 一致性与多核

DMA 与 Cache 一致性.

DMA 的卖点是“不占 CPU 搬数据”，代价是它不经过 CPU 的 cache。于是同一块内存出现两个副本（cache 与主存），谁先谁后没对齐，就会“偶发读到旧数据”。本章给出可执行的规则：按传输方向 clean / invalidate + 按 cache line 对齐 + 屏障。

前置：读过 M04（cache 与写策略）。◷ 约 42 分钟◈ Cortex-M / Cortex-A / RISC-V 对照⚑ 主机模型；目标构建与测量按章验收能力目标：能按 DMA 传输方向正确维护 cache（clean/invalidate），对齐缓冲并加屏障，杜绝“旧数据”偶发。

先确定共享存储的所有者

CPU、DMA 和其他核心可能通过不同缓存路径看到数据。每块缓冲在何时由谁读写、如何发布、何时可复用，要写成协议。按平台文档选择一致性区域、屏障、Cache clean/invalidate 与对齐；volatile 只约束特定编译器访问语义，不能提供整套协议。

本章速览
  • DMA 与 cache：按方向 clean/invalidate。
  • 缓冲按 cache line 对齐。
  • 描述符写后加屏障。

6.1 为什么会出现“偶发读旧数据”

CPU 通过 cache 读写内存，DMA 引擎则直接访问内存。两者看到的是两份副本：CPU 改了 cache 但还没写回内存，DMA 读到的就是旧值；DMA 更新了内存但 CPU 还读 cache，CPU 读到的也是旧值。“偶发”是因为它依赖时序，往往只在压测或特定数据量下出现。

9.3 Amdahl 定律：优化的上限在哪

只优化系统的一部分，整体提速有上限：若某部分占比 p、提速 s，则整体加速 1 / ((1-p) + p/s)。这解释了“局部优化怎么努力都提升有限”。

一句话：先找占比最大的热点

Amdahl 定律说“优化占比小的地方收益有限”。所以别凭直觉优化“看起来复杂的函数”，先用 profiling 找出真正吃时间的那段。

9.4 实时系统要 WCET，不是平均值

实时性关心“最坏情况也满足截止期”。平均时间会掩盖偶发的长分支、cache miss、中断干扰，所以调度分析要用 WCET（最坏执行时间），并覆盖最坏分支与最坏访存路径。

失败路径与排障
  • 不测就优化：方向错，白忙。
  • 只看平均：实时场景下最坏分支超期。
  • 基准环境不一致：不同环境数字不可比。

10.2 贯穿案例：采样→滤波→上报 的预算

以 Cortex-M @72MHz 为例，滤波回路 1M 指令、CPI=1.5：时间 = 1e6×1.5/72e6 ≈ 20.8ms。若把滤波缓冲改成连续访问（M04），miss 减少、有效 CPI 下降；若把控制回路放 TCM（M01），访问不确定性与抖动下降；DMA 搬运上报数据（M06）释放 CPU——这些改动都能在预算里体现。
