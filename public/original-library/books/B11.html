Module 01 · 系统与通信

系统编程.

Linux 应用的底座是系统调用。几乎每个调用都可能失败：必须检查返回值、读取 errno，并处理短读/短写与 EINTR/EAGAIN——“主机上好好的、进板子就崩”常源于此。

前置：C 语言与 Linux 系统调用基础（open/read/write）。◷ 约 44 分钟◈ 三条构建/部署路线对照⚑ 主机模型；目标构建与测量按章验收能力目标：能写出对每个系统调用检查返回值、处理 errno/EINTR/EAGAIN 并循环读满的 I/O 代码。
本章速览
  • 每个系统调用都检查返回值与 errno；EINTR/EAGAIN 要重试。
  • 短读/短写要循环到期望长度。
  • 无超时的阻塞会让程序永久卡住。

1.1 系统调用与 errno：检查返回值是硬规则

系统调用由内核执行，任何一步都可能失败。硬规则：每个调用都检查返回值，失败时读 errno 判断原因。把“不检查返回值”当 bug 处理，是应用稳定的第一步。

1.2 真实证据：循环读满

下面这段主机程序演示有限次 EAGAIN/EINTR 与短读；不代表真实描述符的就绪等待：

host_syscall.cC
/* Bounded I/O control-flow model, not an OS poll/epoll implementation. * Distinguishes partial progress, would-block, interrupted call and EOF. * The outer event-loop wait below is counted, not implemented as busy polling. */#include <stdio.h>#include <string.h>#include <errno.h>typedef struct {const char *data;int size,offset,calls;} ModelFd;static int model_read(ModelFd *f,char *out,int capacity) {    ++f->calls;    if(f->calls==1){errno=EAGAIN;return -1;}    if(f->calls==2){errno=EINTR;return -1;}    int n=f->size-f->offset;    if(n>capacity)n=capacity;    if(n>2)n=2;    memcpy(out,f->data+f->offset,(size_t)n);f->offset+=n;return n;}static int receive(ModelFd *f,char *out,int wanted,int *waits) {    int total=0;    for(int attempts=0;attempts<20 && total<wanted;++attempts) {        int n=model_read(f,out+total,wanted-total);        if(n<0) {            if(errno==EINTR)continue;            if(errno==EAGAIN){++*waits;continue;} /* model: yield and wait for readiness */            return -1;        }        if(n==0)break; /* EOF must not spin */        total+=n;    }    return total;}int main(void) {    ModelFd f={"abcdef",6,0,0};char out[8]={0};int waits=0;    int n=receive(&f,out,6,&waits);    int ok=n==6 && !memcmp(out,"abcdef",6) && waits==1;    ModelFd short_file={"abc",3,0,0};waits=0;    ok &= receive(&short_file,out,6,&waits)==3;    printf("short reads / EINTR / EAGAIN wait / early EOF: %s\n",ok?"PASS":"FAIL");    return !ok;}

1.3 短读/短写与超时

read/write 可能只完成一部分。write 对非阻塞 fd 也可能短写。正确做法是循环直到达到期望长度，并给阻塞操作设超时。

read_full.c 节选C
ssize_t r = 0;while (r < want) {    ssize_t n = read(fd, buf + r, want - r);    if (n < 0) {        if (errno == EINTR) continue;        if (errno == EAGAIN || errno == EWOULDBLOCK) return r; // 返回已读长度，由事件循环等待后继续        return -1;                                        // 真错误    }    if (n == 0) break;      // EOF：对端关闭    r += n;}
片段：EINTR 重试；EAGAIN 返回已收长度由 poll/epoll 驱动继续。生产接口需区分 WOULD_BLOCK、EOF 与完整结果，并设置截止时间

1.5 常见误区与排障

失败路径与排障
  • 不检查返回值：错误被当成成功。
  • 不处理短读：数据截断，协议解析失败。
  • 被 EINTR 打断就失败：信号一来就读不到数据。
  • 无超时的阻塞：链路异常时永久卡住。
◆ 自测 · Module 01（先答再看）

  1. read() 返回 0 表示什么？

    查看答案

    通常表示对端已关闭连接（EOF），不是错误。要据此结束读取循环，而不是继续读。

  2. 为什么 write 也要循环（短写）？

    查看答案

    非阻塞 fd 或缓冲区满时 write 可能只发一部分。必须循环直到发完，否则数据被截断。

  3. EINTR/EAGAIN 分别该怎么处理？

    查看答案

    两者都表示“暂时没完成”：EINTR 是信号打断、EAGAIN 是非阻塞无数据，都应重试（或等待后重试），而不是当致命错误。

Module 02 · 系统与通信

进程间通信.

多进程协作要选对 IPC：管道简单但单向、共享内存最快但要自己同步、消息队列/UDS 保留边界、信号只适合通知。有界队列是常见形态：满则拒、空则等。

  • 信号处理函数里只能做异步安全操作。

2.1 选对 IPC：边界与同步

不同 IPC 的差别在“是否保留消息边界”和“要不要自己同步”：管道是字节流（无边界）、共享内存最快但要配信号量、消息队列/UDS 保留边界、信号只适合异步通知。

2.3 UDS 与共享内存的落地

5.1 竞态与同步

读-改-写不是原子操作：两个线程都先读旧值再写回，后写的覆盖先写的，就丢失更新。所有跨线程共享的可变数据都要用互斥量/原子/条件变量保护。
