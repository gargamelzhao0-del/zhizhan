协议设计基础.

本章速览
  • 帧要能自同步：帧头 + 长度 + CRC；坏帧丢一个，不拖累后面的好帧。
  • 序号用于去重与乱序检测；超时重传必须配合幂等。
  • 版本协商与心跳让两端在升级/断链时行为可预期。

1.1 帧结构：把字节流切成帧

串口给的是字节流，协议要先把它切成一条条帧。最常见结构：帧头 | 长度 | 序号 | 载荷 | 校验 | 帧尾。其中“长度 + 校验”让接收方能在噪声中重新同步：一个坏帧被丢掉，后面的好帧照样能解析。

表 1.1 帧字段
字段作用典型坑
帧头 SOF标记帧开始，便于重同步载荷里出现 SOF → 需转义
长度界定载荷边界长度本身也要被校验
序号去重、检测丢帧/乱序序号回绕要处理
校验 CRC发现传输误码两端参数模型须一致
帧尾 EOF收尾与流控同 SOF，需转义

1.5 常见误区与排障

失败路径与排障
  • 没有长度或定界：只能靠超时切帧，丢字节就永久错位。
  • 不转义：载荷出现帧头/帧尾，接收方提前结束或错位。
  • 重传不去重：对端把同一条命令执行两次。
  • 序号回绕不处理：255→0 被误判为乱序/旧帧。

2.5 常见误区与排障

失败路径与排障
  • 参数模型不一致：一端 0xA001 反射、另一端 0x8005，永远对不上。
  • 初始值/结果异或不同：看似只差一个常数，实为不同标准。
  • 把 CRC 当安全机制：攻击者可改数据同时改 CRC。
  • 硬件 CRC 未复位初值：上一帧余数被带入，结果错。

  1. 为什么换用硬件 CRC 前一定要与软件版对拍？

    查看答案

  3. Modbus TCP 与 RTU 分帧有何不同？

    查看答案

7.5 常见误区与排障

  • 忘记重定位 VTOR：App 中断仍指向 Boot 向量表，一进中断就崩。

  • 直接覆盖运行区：写一半掉电就没有可启动固件，必砖。

◆ 自测 · Module 08（先答再看）

  1. 为什么“CRC 通过”不等于“固件安全可信”？

    查看答案

    CRC 只保证数据未被误码破坏，任何人都能算出正确 CRC。防篡改/防伪造必须校验数字签名（或带密钥的 MAC），密钥留在可信存储。

  2. 为什么回滚能力是 OTA 的最后一道保险？

    查看答案

    新固件可能因兼容/资源问题启动失败；未确认前保留旧固件并在自检失败时退回，才能避免设备变砖。

  3. 断点续传解决什么问题？

    查看答案

    大固件在弱网下常下载中断；按块记录已收进度，重连后只补未收块，避免全量重传、提高成功率。

10.5 常见误区与排障

失败路径与排障

◆ 自测 · Module 10（先答再看）

  1. 升级任务为什么一般设成低优先级？

    查看答案

    升级是“能慢不能断”的批量活。设低优先级，业务可随时抢占它；若设高优先级，长时间下载会挤占采集与控制，破坏实时性甚至触发看门狗。

  2. 共享串口为什么要加锁？

    查看答案

    轮询帧与升级数据若交错，两端都会解析失败。用互斥量把链路访问串行化，保证一帧完整发完再发下一帧。

  3. 为什么要把协议契约、日志与版本贯穿始终？

    查看答案

    现场出问题时，只有靠明确的协议契约、可回溯的日志与统一版本号才能定位是固件/协议/参数哪一层的问题，否则无从复盘。

◆ 自测 · Module 12（先答再看）

  1. 为什么退避要加“抖动（jitter）”？

    查看答案

    大量设备同时断线若都用相同退避，会在同一时刻一起重连，造成服务器雪崩。加随机抖动把重连时间打散，削峰填谷。

  2. 有界缓存在满时应该怎么办？

    查看答案

    要么丢最旧（并计数），要么阻塞上游（带超时），绝不能悄悄堆积到 OOM；溢出策略要明确且可观测。

  3. 补传为什么要“只补缺失”？

    查看答案

    重连后全量重发会浪费带宽、放大网络压力并可能造成乱序；按序号只发未确认的部分更高效。

13.5 常见误区与排障

失败路径与排障
  • 只升镜像不管参数：新固件按新结构读旧配置，读出垃圾。
  • 允许降级：旧固件读不懂新参数/新协议，直接把设备弄坏。
  • 无回退边界：迁移不可逆却承诺“可回滚”，回滚后状态错乱。
  • 确认时机太晚：跑了几小时才确认，期间坏固件一直在现场运行。
◆ 自测 · Module 13（先答再看）

  1. 为什么协议要“向后兼容”，而镜像往往“不允许降级”？

    查看答案

    协议对端（网关/云）可能版本不一，需兼容旧客户端；而固件降级常伴随不可逆的参数迁移与安全补丁回退，允许降级会引入更大风险，通常只允许受控回滚到已知版本。

  2. 参数版本变更为什么要配“带默认值的迁移函数”？

    查看答案

    新固件可能读到旧结构或旧固件读到新结构；迁移函数按默认值补齐缺失字段、转换含义，使配置在版本升级时仍然可用。

  3. “回退边界”为什么必须写清楚？

    查看答案

    有些迁移不可逆（如参数结构升级后旧固件读不懂新参数）。若不写清哪些能回、哪些不能，回滚后状态错乱，反而更危险。

◈ 10 步集成路径⚑ 每步可验收

把 13 章的能力串成一个可交付节点：平时按 Modbus 轮询传感器并经 MQTT 上报；收到升级命令后，下载固件写入备用区，校验通过再切换；新固件自检通过前不确认，失败可回滚。这不是新示例，而是把各章按依赖重排成一条构建路径，每一步都有可检验的验收。

  1. ① 定协议（M01/M02）——帧头+长度+CRC，序号去重；验收：注入噪声后仍能重同步，坏帧不影响好帧。
  2. ② 现场总线（M03/M04）——Modbus 轮询 + CAN 采集；验收：整帧 CRC 自洽、异常码可分、CAN 位定时/终端正确。
  3. ③ 联网（M11）——以太网/WiFi + TCP；验收：分层（link→IP→TCP）逐层可观测。
  4. ④ 上行（M06）——MQTT QoS1 上报；验收：重复消息被去重，掉线由遗嘱暴露。
  5. ⑤ 断网兜底（M12）——指数退避 + 有界缓存；验收：断网不丢数据、缓存有上界、重连后补传。
  6. ⑥ 无线补充（M05）——BLE/LoRa 视场景接入；验收：连接参数/占空比符合约束。
  7. ⑦ 分区与跳转（M07）——Boot/App/备份分区；验收：跳转前关中断、重定位 VTOR、设 MSP。
  8. ⑧ 升级链路（M08）——分块下载 + 断点续传 + 校验；验收：任一步掉电都能启动。
  9. ⑨ 确认与回滚（M13）——版本准入 + 自检确认；验收：不降级、跨版本先迁移、失败回滚。
  10. ⑩ 整合（M09/M10）——labs/capstone_ota_node.c：共享链路加锁、升级优先级低于业务、现场可诊断。

帧 / 分帧 (Framing)
把字节流切成一条条消息；帧头/长度/CRC 使其可自同步。
转义 (Escaping / COBS)
把与帧头/帧尾冲突的字节用转义序列表示，常见 COBS/字节填充。
CRC 参数模型
多项式、初值、输入/输出是否反转、结果异或；四项不同结果就不同，必须两端一致。
MODBUS RTU
一主多从、帧间静默分帧、CRC16 校验；功能码 0x03/0x06 等读写寄存器。
寄存器映射
把设备参数对应到寄存器地址与单位，是 Modbus 集成的契约。
CAN 仲裁
多主同时发送时按 ID 逐位仲裁，ID 越小优先级越高，输者自动重发。
位定时 / 采样点
位时间分成同步段+BS1+BS2；采样点位置影响长线抗扰与同步。
总线关闭 (Bus-off)
CAN 错误计数过高进入总线关闭，需自动恢复流程。
GATT
BLE 的属性数据模型：服务/特征/描述符，Notify 用于低功耗上报。
连接参数
BLE interval(1.25ms 单位)与 latency(10ms 单位)权衡功耗与响应。
扩频因子 (SF)
LoRa 参数，越大越远越慢；还需遵守地区占空比限制。
MQTT QoS
0 至多一次 / 1 至少一次 / 2 恰好一次；QoS1 需去重，QoS2 需四步握手。
保留消息 / 遗嘱
Retain 保存最后一条；LWT 在客户端异常掉线时由代理发布。
CoAP
面向受限设备的 REST 风格协议，基于 UDP，适合低功耗。
TLS 开销
握手需额外 RAM 与数秒时间；MCU 上常用精简套件/会话复用。
Bootloader / 跳转
上电先跑的小程序；跳转前要关中断、重定位向量表、设 MSP。
A/B 分区 / 双 Bank
两个固件区交替升级：写备用区，校验后切换，失败可回滚。
回滚 (Rollback)
新固件未确认或自检失败时切换回旧固件，保证“永远不会变砖”。
幂等 (Idempotent)
同一命令重复执行结果不变；重传/去重的基础。
指数退避
重连间隔随失败次数指数增长并封顶，避免雪崩。
背压 (Backpressure)
当下游处理不过来时，用有界缓存/丢弃/阻塞上游来控制压力。
ARP / DHCP / DNS
链路之上的地址解析、动态取址与域名解析；排障要逐层看。
pbuf / socket
lwIP 的报文缓冲与分析接口；应用多用 socket，注意半包/粘包。
