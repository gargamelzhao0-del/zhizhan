Module 01 · 预算与数据

端侧 AI 全景与算力预算.

端侧 AI 的第一步不是选模型，而是算预算：可用算力（MAC/s）、内存、延迟期限、功耗。预算决定了模型规模与是否量化/加速。

前置：C 语言与信号采样基础。◷ 约 44 分钟◈ 端/边/云三级对照⚑ 主机模型；目标构建与测量按章验收能力目标：能为目标模型算出 MAC 数、峰值内存与延迟截止期，并据此选定模型规模。

峰值内存不是各层 tensor 大小简单求和

峰值由张量同时存活的集合、工作区、对齐与运行时开销决定。按每一步列出仍存活的输入/输出；跳连可能延长生命，可复用缓冲则降低峰值。权重常驻量、激活峰值和整机 RAM 预算分别记录；数组求和可当保守上界，不能称实际峰值。

本章速览
  • 先算算力/内存/延迟/功耗预算，再定模型规模。
  • 延迟由少数最重层主导，优化优先它们。
  • 预算→设计→测量闭环。

2.2 真实证据：特征口径一致

下面这段程序计算时域特征（数值均为同一量纲），用于核对训练与推理口径：

/* host_feature.c —— 时域特征：均值/去直流 RMS/峰值/峰峰值（主机可运行）。 * 编译运行：gcc -std=c11 -Wall -Wextra -O2 host_feature.c -o host_feature && ./host_feature */#include <stdio.h>#include <math.h>int main(void) {    int ok = 1;    float x[] = {1,2,3,4,5,6,7,8};    int n = (int)(sizeof(x)/sizeof(x[0]));    float sum = 0; for (int i = 0; i < n; i++) sum += x[i];    float mean = sum / n;    float ac = 0, peak = 0, vmin = x[0], vmax = x[0];    for (int i = 0; i < n; i++) {        float d = x[i]-mean; ac += d*d;        float a = fabsf(d); if (a > peak) peak = a;        if (x[i] < vmin) vmin = x[i];        if (x[i] > vmax) vmax = x[i];    }    float rms = sqrtf(ac/n);    float pp = vmax - vmin;            /* 峰峰值由数据计算，不是硬编码 */    printf("mean=%.2f rms(ac)=%.3f peak=%.2f peak-peak=%.1f\n", mean, rms, peak, pp);    if (fabsf(mean-4.5f) > 1e-4) ok = 0;    if (fabsf(rms - 2.2913f) > 1e-3) ok = 0;   /* 去直流后 RMS = sqrt(5.25)=2.2913 */    if (fabsf(peak-3.5f) > 1e-4) ok = 0;    if (fabsf(pp-7.0f) > 1e-4) ok = 0;         /* max-min = 8-1 */    printf("\n%s\n", ok ?   1. 异常检测中为什么“漏报率”常比“误报率”更重要？

    查看答案

    漏报意味着真正的异常没被发现，后果可能是事故；误报只是打扰。所以要按业务后果设阈值，通常优先压低漏报。

  2. 为什么“只看准确率”会误导？

    查看答案

    类别不平衡时，全靠预测多数类也能有高准确率。要看 precision/recall/F1 与漏报/误报率。

  3. precision 和 recall 分别衡量什么？

    查看答案

    precision 衡量“报出来的有多准”（TP/(TP+FP)）；recall 衡量“真正例抓到了多少”（TP/(TP+FN)）。两者此消彼长，按业务取舍。

    数据分布会随时间变化（漂移），模型精度悄悄下降。监测漂移并触发重训才能保持效果。

◆ 自测 · Module 11（先答再看）

  1. 为什么“数据拷贝”常是异构推理的隐藏瓶颈？

    查看答案

    CPU 与加速器间搬数据要走总线/内存，带宽有限且可能与计算争用；拷贝时间可能超过计算时间。零拷贝/共享缓冲能显著降低。

  2. 加速后为什么还要检测“算子回退”？

    查看答案

    不支持的算子会静默回退到 CPU，导致“看起来用了加速器实际没有”。检测回退占比才知道真加速。

  3. 为什么加速器常要求定点（量化）？

    查看答案

    NPU/DSP 对定点（int8）有专用流水线更高效；浮点或量化不匹配的模型无法被加速，只能回退 CPU。

13.1 三方版本与接口契约

模型 / 预处理 / 固件三方必须版本配对：模型变了预处理要同步、固件算子要支持新模型、张量形状/类型（接口）不能变。任一错配，精度崩或加载失败。

13.5 常见误区与排障

失败路径与排障
  • 只升模型不升预处理：精度崩。
  • 固件算子不支持新模型：加载失败。
  • 张量形状/类型变：接口错配崩。
  • 回退无边界：退回后状态错乱。
◆ 自测 · Module 13（先答再看）

  1. 为什么端侧 AI 要把“预处理版本”也纳入管理？

    查看答案

    预处理（归一化/特征）与模型是配对的；模型假设的输入分布由预处理决定。只升模型不改预处理，输入分布就变了，精度崩。

  2. “兼容矩阵”解决什么问题？

    查看答案

    明确哪些模型版本可与哪些固件/预处理组合，升级时校验三方配对，避免错配导致加载失败或精度崩。

  3. 为什么回退要有边界？

    查看答案

    某些升级不可逆（如预处理结构变化）。若无边界地回退，可能出现“旧模型 + 新预处理”的错配组合，状态错乱。
