Module 01 · 模块与字符设备

内核模块基础.

内核模块是一段可动态加载进内核的代码：module_init 注册、module_exit 注销。它受 vermagic 与依赖约束，被 引用计数保护。读懂这三点，就理解了所有驱动的共同底座。

前置：C 语言与 Linux 命令行；能编译并运行主机 C 程序（labs/host_*.c）。◷ 约 42 分钟◈ 三平台驱动对照⚑ 主机模型；目标构建与测量按章验收能力目标：能写出带 module_init/exit、module_param 与引用计数检查的可加载/卸载模块骨架。
本章速览
  • 模块有 init/exit 与引用计数；ref>0 不能卸载，重复 init 返回 -EBUSY。
  • 用 module_param 暴露配置，用 vermagic 校验内核版本。
  • init 失败要把已注册资源回滚，成功路径与失败路径对称。

1.1 模块生命周期：init / exit / 引用计数

模块加载时内核调用 module_init 注册的资源，卸载时用 module_exit 一一注销。两者必须对称：init 里做了一半失败，要把已做的回滚；否则下次加载冲突。而“能不能卸载”由引用计数决定——还有使用者（ref>0）时强行卸载会留下悬空指针。

1.5 常见误区与排障

失败路径与排障
  • init 失败资源已注册却不注销：下次加载冲突。
  • 忽略引用计数：rmmod 时仍在使用，内核崩溃。

◆ 自测 · Module 01（先答再看）

  1. 为什么 rmmod 要在引用计数归零后才能成功？

    查看答案

    ref>0 说明还有打开的文件/使用者持有驱动资源；此时卸载会留下悬空指针与已释放资源，内核用引用计数保证安全卸载（返回 -EBUSY）。

  2. 模块“能编译但加载失败”，先看什么？

    查看答案

    先看 vermagic 是否与运行内核一致（dmesg 会提示 invalid module format），再看依赖模块是否已加载（modprobe 会自动解决，insmod 不会）。

  3. module_init 里注册了设备后又注册中断失败，应该怎么做？

    查看答案

    回滚已注册的设备（注销）再返回错误码。失败即回滚是模块稳定的第一纪律，否则残留下次加载会冲突。

答完再看解析；不确定的点回到对应小节复读。

Module 02 · 模块与字符设备

字符设备.

字符设备是“以字节流访问”的设备：内核把用户态的 open/read/write/ioctl 分派到驱动的 file_operations。主设备号标识驱动，次设备号标识实例。安全的关键是：用户指针必须用 copy_*_user。

前置：Module 01 模块生命周期与引用计数。◷ 约 44 分钟◈ 三平台驱动对照⚑ 主机模型；目标构建与测量按章验收能力目标：能写出按 minor 分派 open/read/write/ioctl、用 copy_*_user 的字符设备驱动骨架。
本章速览
  • 字符设备把 open/read/write/ioctl 分派到 file_operations；主/次号标识驱动与实例。

8.1 为什么 DMA 会读到旧数据

CPU 走 cache，DMA 绕过 cache 直连内存：两者看到两份副本。CPU 改了 cache 未写回 → DMA 读旧值；DMA 改了内存而 CPU 还读 cache → CPU 读旧值。表现为“偶发”，压力大时才暴露。

12.6 常见误区与排障

  • 不 get 就访问硬件：设备处于 suspend，访问异常。
