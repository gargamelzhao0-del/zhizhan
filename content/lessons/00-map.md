# 学习地图：把项目经验连成可验证的能力

## 目标：知道自己下一步该练什么

本库有三种材料：真实产品的工程快照、从零开始的小实验、问题处理方法。工程手册用于理解复杂系统，小实验用于隔离变量，复盘用于建立证据。不要把“读完全部文章”当作学习目标；你应能独立写程序、解释行为，并交付别人能重复的结果。

开始前先回答：能否解释指针有效期、区分进程和线程、从日志分离事实与猜测？不会时按下面的入口补基础。全库无需按文件编号从头背到尾。

| 当前问题 | 基础入口 | 实践入口 | 应保留的成果 |
| --- | --- | --- | --- |
| 程序为什么随机崩溃 | [C 与内存](doc:handbook-01)、C++ 生命周期 | RAII 文件计数 | 对象与资源所有权图 |
| 线程停止后数据为什么少了 | 并发队列 | 采样记录检查器 | 关闭、排空、join 的测试 |
| 编译通过但板上不能运行 | Linux 分层 | 交叉编译 | ELF 与工具链指纹 |
| 文件保存了却不完整 | 文件 IO | 复制工具交付 | 大小、哈希、错误退出码 |
| 升级后用户资料怎么办 | [知栈更新案例](doc:lessons-04) | 创建笔记并演练内容更新 | 更新前后的数据核对表 |
| 问题有时出现、有时正常 | [证据与推理](doc:lessons-02) | [最小复现](doc:lessons-05) | 可证伪假设和原始记录 |

## 四周练习安排

每周建议三次 45～60 分钟，可按基础调整。卡住时减少任务规模，不需要为了进度跳过解释。

**第一周：资源。** 按独立书库 B02a 的对象与资源管理小节练习；使用 C 的项目则练习 B00 的对象生命与错误处理。画出 owner 与 view，演示一次 vector 扩容为何不能继续使用旧引用；用安全程序验证容量与大小，而不是主动解引用悬空指针。成果是自己的解释和可运行代码。

**第二周：并发与输入。** 完成 C++ 第 4～7 课。先写输入契约，再实现有界队列；对空输入、非法行、超长行、关闭时残留数据做验证。成果是接受数、拒绝数、总和及退出码的自动核对。

**第三周：Linux 工具链与 IO。** 完成 Linux 第 1～3、6～7 课。没有开发板可在 Linux PC 做用户态实验，把板端验收留空；没有 Linux 环境则先读源码并画调用图，不能填写“已通过”。设备树和模块第 4～5 课按环境补做。

**第四周：真实工程与复盘。** 从工程手册挑一个与你实验相关的模块，跟踪“输入 → 队列 → 工作任务 → 持久化或网络 → 确认”。找出等待、所有权和错误路径，将一个问题缩成十步以内可复现的案例。避免一开始就同时改驱动、任务优先级与协议。

## 如何使用知栈保存成果

每次实验创建一篇自己的文章，正文写目标、环境、命令、预期、实际、结论；附上最小源码或日志。课程的“个人笔记”适合记疑点，长篇实验记录适合单独建文并链接课程。收藏用于入口，阅读进度用于找位置，复习日期用于回看；它们都不替代验收。

推荐复习动作：隔天不看答案重新解释一次，隔一周改一个边界条件再运行。解释不通就回到对应课，记录“我之前的错误理解 → 新证据 → 修正”。

## 完成条件与自测

每个主题需满足三个条件：能预测至少一条边界行为；能运行并核对结果；能说明一个尚未验证的限制。使用“看过、练过、可复现”三种状态写在笔记里，比笼统的“掌握了”更准确。

练习：某队列例子连续运行 100 次成功，是否可标为“无竞争缺陷”？参考答案：不能。有限运行是证据的一部分，还要检查共享数据访问、停止协议、唤醒条件和异常退出；未覆盖的调度仍可能触发问题。

练习：Linux 程序还没运行，是否可以记录学习成果？答案：可以保存代码审阅和预测，但将执行证据标为缺失，不能混写为验收成功。这能让下次学习准确接续，而不是重复猜测。
