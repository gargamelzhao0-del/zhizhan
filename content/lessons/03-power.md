# 03 · 电量与充电：传感器读数不等于用户状态

## 案例范围与学习目标

来源：[电源、充电与指示灯](doc:handbook-05) 和 [历史问题](doc:handbook-22)。这是基于项目硬件与代码快照的教学案例，不是对任意电池或充电器的通用改造指南。本课没有测量当前设备电流或温度。预计 45 分钟。

## 四个不同问题

1. USB 是否物理插入？
2. 供电端是否有足够能力？
3. 电池是否正接受净充电电流？
4. 软件图标与 LED 应表示哪个状态？

这四者有关联，但不能互相替代。设备运行也消耗电流，电池净电流与适配器提供的总电流不是同一个数。高电量阶段、电量计估算、温度/保护状态也会影响观察结果。

当前案例里，电量计负责测量/估算，充电芯片负责充电控制。用于 UI 判定的电流阈值不能被误认为设定充电电流的寄存器。电流正负方向也必须依据芯片和驱动的约定核实，不能凭符号直觉下结论。

## 用状态表指导排查

| 观察 | 可以支持 | 还不能支持 |
| --- | --- | --- |
| 串口 USB 在线 | 当前 USB 通道可用 | 适配器充电能力足够 |
| SOC 从 97 到 100 | 电量计估算发生变化 | 每分钟真实充入固定容量 |
| 净电流多次为充电方向 | 采样时电池接受净电流 | 后续一直充电、已达到额定电流 |
| FC/充满标志 | 按驱动解释的硬件状态 | 所有图标状态均正确 |

用原始电压、电流、SOC、状态标志和时间一起分析，不能只看百分比。引用的原工程记录可能随硬件/固件变化，要以实际版本重新确认。

## 阈值、滤波和优先级

显示状态可以采用迟滞与连续样本：进入充电和退出充电用不同条件，降低电流接近零时闪烁。但具体阈值和时间需要实测，不能为了让图标亮而掩盖传感器故障。插入、有效充电、充满、测量不可用也应有定义，不应全部压成一个布尔量。

低电平点亮的 LED 要把逻辑亮度映射为正确电平/PWM。软件任务是否把灯控制权交给其他状态，也影响结果。检查原理图极性、GPIO 复用、PWM 端点、任务优先级和最终输出，不仅看充电布尔值。

## 练习与验收

画一张状态机，并为每条边写证据：插入、拔出、有效充电、接近充满、读数失败。按固定间隔记录样本，说明滤波后的判定为何成立。若拔线后无法取得串口日志，设计本地历史记录或其他已授权的观测方式，不能补造缺失数据。

不要在这道软件练习里直接提高充电电流或忽略温控保护；硬件安全范围需要原理图、芯片资料和电池规格共同约束。

## 自测与答案

**百分比不涨就证明完全没充电吗？** 不能，估算粒度和负载等因素都需结合原始数据。

**亮灯是否代表代码真的发了充电状态？** 不一定，可能极性反了或另一个任务覆盖 GPIO。

**验收：** 区分测量事实、软件状态和显示效果，能提出一个不依赖猜测的采样与验证计划。
